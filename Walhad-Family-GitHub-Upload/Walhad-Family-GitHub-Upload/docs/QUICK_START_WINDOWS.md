# Simple Windows run guide

**Status: source/checks complete for this iteration; real-device validation pending. Not ready for release.**

## A. First run without a service account

You can inspect source and rerun local checks without paid credentials. You cannot send real production messages or make calls until section B is completed.

1. Install Node **22 LTS** (22.12+), Git and **JDK 21**.
2. Extract the source ZIP and open PowerShell in `walhad-family-mobile`.
3. Run:

   ```powershell
   npm ci
   npm --prefix functions ci
   npm run typecheck
   npm --prefix functions run build
   npm test
   npm run test:dependencies
   npm run test:rules
   npx expo-doctor
   npm run bundle
   ```

4. The test project `demo-walhad` runs locally. Expected: 4 logic tests, 9 dependency-compatibility tests, 16 Firestore/Storage tests, and both JS bundles. It does not contact a real Stream app or prove phone behavior.

## B. Make real messaging and calling work

1. **Firebase:** create a billing-enabled project; enable Email/Password, Firestore and Storage. Add a Firebase **Web app** for its JavaScript SDK configuration.
2. Run `Copy-Item .env.example .env`. Fill in the Firebase configuration, Stream public key and Expo project ID. Detailed instructions for obtaining each are in [README](../README.md).
3. **Stream:** create a Video app, obtain its key/secret, restrict room permissions to actual room members. Keep the secret out of `.env` and out of the phone app.
4. **Expo:** run `npx eas-cli login` and `npx eas-cli init`. Put the Expo project UUID in `EXPO_PUBLIC_EAS_PROJECT_ID`. Create an Expo push access token and enable enhanced push security.
5. Deploy backend configuration:

   ```powershell
   npx firebase login
   npx firebase use --add
   npx firebase functions:secrets:set STREAM_SECRET
   npx firebase functions:secrets:set EXPO_ACCESS_TOKEN
   npx firebase deploy --only firestore:rules,firestore:indexes,storage
   npx firebase deploy --only functions
   ```

   Choose the **real Firebase project**, not `demo-walhad`. Supply the public Stream API key when function deployment prompts for it.
6. For **Android push**, register the package in Firebase, download `google-services.json` into the project root, upload that build file to EAS and configure FCM v1 credentials. For **iOS**, configure Apple signing and APNs in EAS. Follow README steps 2–5; these credentials cannot be generated by this source archive.
7. Upload `.env` public variables to the EAS development environment:

   ```powershell
   npx eas-cli env:push --environment development --path .env
   npx eas-cli env:create --environment development --name GOOGLE_SERVICES_JSON --type file --value .\google-services.json --visibility secret
   ```

   The file-variable command is for Android. Never upload a service-account secret as a public environment variable.

## C. Install and open the real app

**Android**

```powershell
npx eas-cli build --platform android --profile development
```

Install the APK from the resulting EAS link on the actual phone.

**iPhone** — Apple Developer membership/signing required for this workflow:

```powershell
npx eas-cli device:create
npx eas-cli build --platform ios --profile development
```

Register the iPhone, install the signed build from EAS, and enable Developer Mode if requested. Windows can request this cloud build; Windows cannot run Xcode.

**Start JavaScript:**

```powershell
npm start -- --clear
```

Open the installed development app and its Metro link. Do **not** open Expo Go. Keep the PC/phones on the same Wi-Fi; use `npx expo start --dev-client --tunnel` if needed.

## D. Test it, using two phones

1. Register two different emails; verify both.
2. Find each other under **People**. Send messages both ways; restart and check history.
3. Upload pictures, save names/bios, and observe online/offline expiry.
4. Make an audio call, accept, talk, mute and hang up. Repeat with video and different networks.
5. Background/lock the receiver. Test message and incoming-call notifications, then tap them. Do not assume delivery or native phone-style ringing.
6. Test permission denial, blocking/reporting, sign-out and deletion using disposable data.
7. Record results in [DEVICE_TESTS](DEVICE_TESTS.md).

**Important:** normal call push alerts are implemented; full native CallKit/locked-screen ringing is not. Signed native builds, real-device tests and dependency remediation remain required before any release decision. No app-store approval or publication has happened.
